## 1 · 剧本(2 小时,¥0.01)

> **本阶段目标**:产出 1 份完整的 6 镜头剧本表,存放在 Toonflow 项目内,后续所有阶段(角色/分镜/视频)都从这份剧本出发。
>
> Toonflow 不是编剧软件,但有 3 种方式落地剧本阶段,从「最轻」到「最深度集成」排列。**推荐方式 1+2 组合**。

### 1.1 方式 1 · 文档视图(推荐 · 存稿用)

Toonflow 顶部右侧有 **「画布 / 文档」** 切换标签,**「文档」**视图是项目级的写作区域,剧本存这里最合适——和 Toonflow 工程同位,换电脑能找回,且能被 AI 助手直接引用。

**操作步骤**:

1. 画布顶部右上角点 **「文档」** 标签(在「画布」右边)
2. 进入文档工作区 → 左侧栏选 `myProject`
3. 顶部工具栏点 **「新建」**(或加号图标)
4. 命名文档:`最后一盏灯·剧本`
5. 在编辑器里粘贴下面的 6 镜头剧本表
6. **Ctrl/Cmd + S** 保存

**优势**:
- 剧本和项目绑定,跨设备同步
- AI 助手能直接读这份文档作为上下文,后续阶段改提示词不用重新粘贴
- 团队协作时其他人也能看到

---

### 1.2 方式 2 · AI 助手对话生成(适合没想法起步 · 5 分钟)

如果你**完全没剧本**或者想偷懒,让 Toonflow 的 AI 助手从零生成草稿。

**操作步骤**:

1. 画布顶部右侧点 **AI 助手图标**(右上角圆球/AI 头像)
2. 弹出助手面板,底部有输入框
3. 直接发送:

```
我要做一个 30 秒的日系动漫漫剧,主题是「雨夜温暖」,
请帮我生成完整剧本,要求:
- 2 个角色:23 岁外卖女骑手 + 60 岁便利店男老板
- 6 个镜头,每个 5 秒
- 日系动漫风格,温馨但不腻
- 包含:故事大纲 + 6 镜头表(含画面/景别/对白/音效)

输出格式:Markdown,可以直接复制粘贴。
```

4. 助手调用 `deepseek-v4-flash-sg`(¥0.001 / 1k token)输出草稿
5. **复制助手输出** → 切到「文档」视图 → 新建剧本文档 → 粘贴 → 微调 → 保存

**助手输出长这样**:

```markdown
## 故事大纲
雨夜深巷,外卖女骑手小雨在最后一份订单结束后,
疲惫地想找个地方避雨。她推开街角便利店的门,
发现 60 岁的陈伯——这个素不相识的老人,
居然一直为她留着灯、备着热水。两人没有过多交谈,
一杯热水、一句「总得留盏灯,给晚归的人」,就让
这个雨夜变得温暖。

## 6 镜头剧本表
| 镜头 | 时长 | 画面 | 景别 | 对白 | 音效 |
|---|---|---|---|---|---|
| 1 | 5s | 雨夜便利店外景,暖黄灯光从玻璃门透出 | 全景 | (无) | 雨声 |
| 2 | 5s | 小雨穿着蓝色雨衣推门进来,雨衣滴水 | 中景 | (无) | 推门声 |
| 3 | 5s | 小雨犹豫开口 | 中近景 | 老板,还能借我站一会儿吗? | 雨声渐弱 |
| 4 | 5s | 陈伯把水杯推到柜台 | 近景 | 先暖暖手。 | 推杯声 |
| 5 | 5s | 小雨双手捧杯放松 | 中近景 | 我以为这么晚,没人等我了。 | 蒸汽声 |
| 6 | 5s | 两人隔杯相视而笑 | 中景 | 总得留盏灯,给晚归的人。 | 雨声渐起 |
```

### 1.3 方式 3 · 画布 textNode(适合把剧本接入自动化)

如果你想让剧本**自动驱动**后续 AI 生成(让 AI 自动从剧本读出 6 段视频提示词),可以用 textNode 把剧本存进画布。

**操作步骤**:

1. 顶部右侧切回 **「画布」**
2. 在画布左上角(角色图节点上方)右键 → 添加节点 → **「文本」** / **「text」**
3. 节点标题改成 `剧本`
4. 节点正文里粘贴完整的 6 镜头表(Markdown 或纯文本都行)
5. **不连线**,这是剧本的「画布内备份」

**这个节点的实际作用**:

- 后续阶段 4 / 5 时,可以对 AI 助手说:**「请读画布上 `剧本` 节点的 6 镜头表,自动生成 6 段视频提示词」**,助手能从画布节点读内容
- 不用每次重新粘贴剧本

## 2 · 角色资产(15 分钟,¥0.12)

**目标**:固定角色外观,后续 5 个镜头都引用这些图,保证角色一致。

### 2.1 画布准备:5 个图片生成节点

1. 进入 Toonflow 画布 1
2. 在空白处**右键 → 添加节点 → 图片生成** → 重复 5 次
3. 拖成一行,节点标题栏依次改成:
   - 小雨·正面
   - 小雨·侧面
   - 陈伯·正面
   - 陈伯·侧面
   - 便利店·全景

### 2.2 每个节点的固定配置

| 项 | 值 |
|---|---|
| 模型 | 通义万相 Qwen-Image-3.0 |
| 比例 | **1:1**(角色立绘用方形) |
| 分辨率 | 1K |
| 张数 | 1 |

### 2.3 5 张图的提示词(逐字复制)

**小雨·正面**
```
日系动漫风格,二次元,23岁外卖骑手,黑色齐耳短发,刘海
斜分贴在脸颊,深棕色圆眼睛,鼻梁细窄,薄嘴唇,蓝色半透明
塑料雨衣,内搭黑色长袖,深灰色长裤,黑色橡胶雨靴,右手
戴灰色棉手套,左手空着,纯色浅灰背景,全身立绘,正面朝向
镜头,1:1方形构图
```

**小雨·侧面**(把上面提示词的「正面朝向镜头」改成「左侧面朝向镜头」,其他一字不动)

**陈伯·正面**
```

灰白短发,米色衬衫外套深棕色围裙,表情温和慈祥,
深棕色眼睛,纯色浅灰背景,半身立绘,正面朝向镜头,
1:1方形构图
```

**陈伯·侧面**(同上,把「正面」改「左侧面」)

**便利店·全景**(场景图)
```
日系动漫风格,二次元,雨夜街角便利店外景,暖黄色灯光
从玻璃门透出,玻璃上有雨水流痕,街面湿润反光,深蓝色
夜雨背景,便利店招牌模糊可见,氛围温馨略带孤独,9:16竖屏
```

### 2.4 跑图与验收

每个节点选中 → 右下角 ▶️ → 等 30–60 秒。

**挑图规则**:
- 三张人物图(小雨正/侧、陈伯正/侧)**脸必须像同一个人**,不接受任何「脸漂移」
- 如果重跑 3 次还不满意,在该节点提示词末尾加最冷描述(如「江淮一带女性脸型,普通偏瘦身材」),再试

**验收清单**:
- [ ] 小雨两张雨衣颜色都是**半透明蓝**
- [ ] 陈伯两张围裙颜色都是**深棕色**
- [ ] 背景都是浅灰纯色

## 4 · 视频生成(30 分钟,¥4.50)

**目标**:6 张分镜图 → 6 段 5 秒视频,共 30 秒。

### 4.1 画布准备:6 个视频生成节点

右键 → 添加节点 → 视频生成 × 6。

### 4.2 每个节点的固定配置

| 项 | 值 |
|---|---|
| 比例 | 9:16 |
| 分辨率 | 720P(必须,大写) |
| 时长 | **5 秒** |
| 生成音频 | **关**(我们用 TTS 单独配音) |

#### 4.2.1 选择模型(分线指南)

**重要**:不同模型支持的输入语义不同,选错了节点会提交失败或语义错误。

| 模型 ID | 输入协议 | 适合镜头 | 价格 |
|---|---|---|---|
| `wan2.6-r2v-flash` | `input.reference_urls: string[]` | 1-5(单图参考生视频) | ¥0.15/s |
| `wan2.7-i2v` | `input.media[]` (first_frame / last_frame) | 6(首尾帧生视频,首选) | ¥0.6/s |
| `wan3.0-video` | `input.media[]` (4 reference_image 槽) | 角色一致性要求高的镜头 | ¥0.3/s |

**对应节点的模型下拉**:

| 节点 | 模型 | 理由 |
|---|---|---|

## 10 · 排错手册

### 10.1 图片生成 400「模型 ID 不能重复」

**症状**:图片节点弹 HTTP 400。

**原因**:`compshareMedia.ts` 旧版本残留的异步 fallback 调用 ModelVerse task_type 错误。

**修复**:用最新版的 `compshareMedia.ts`(已含 `resolveImageSize` + 关闭异步 fallback),重新粘贴到 Toonflow 设置面板。

### 10.2 「获取模型」按钮报「模型 ID 重复」

**症状**:点「获取模型」后弹「模型 ID 重复」。

**原因**:`modelsUrl` 字段指向 ModelVerse 动态列表,与硬编码模型撞 ID。

**修复**:最新版 `compshareMedia.ts` 已删除 `modelsUrl` 字段,该按钮自然消失。

### 10.3 视频生成 HTTP 400「Invalid param: unsupported resolution」

**症状**:视频节点报 `HTTP 400 {"error":{"message":"...unsupported resolution: 480P, supported: 480P, 720P, 1080P"}}`。

**根因**:Wan2.7 图生视频只支持 `720P` / `1080P`。节点会把供应商声明的分辨率按数值升序排序，保留有效的旧值，所以仅把 `720P` 写在数组第一项无法阻止选中 `480P`。平台错误里的通用支持列表不能代表该模型的实际能力。

**修复（供应商 1.0.2）**:从 `wan2.7-i2v` 能力列表中移除 `480P`；提交前拒绝旧客户端或 Agent 传入的 `480P`，提示选择 `720P` / `1080P`。刷新页面后，已有节点会自动将无效分辨率归一到 `720P`。

**相关错误：`last_frame must be accompanied by first_frame`**

Toonflow 的 `startFrameOptional` 表示「首帧可选」，单张图片会作为尾帧发送。Wan2.7 / Wan3.0 的图生视频应使用 `endFrameOptional`（「尾帧可选」），单图作首帧，双图依次作首帧、尾帧。1.0.2 已修正这两个模型的模式声明，并在提交前拦截仅尾帧请求。刷新页面重新加载供应商后，选择「尾帧可选」即可；无需重建节点。

### 10.4 视频生成 HTTP 400「所有视频模型均失败」

**症状**:视频节点跑起来后,后端日志或节点 UI 显示
`视频任务提交失败：HTTP 400`;所有 `wan2.7-i2v` / `wan2.6-r2v-flash` / `wan3.0-video`
都报一样的错。

**根因**(2026-09-29 已修复):
ModelVerse `/v1/tasks/submit` 真实协议是嵌套结构:

```json
{
  "model": "wan2.6-r2v-flash",
  "input":    { "prompt": "...", "reference_urls": ["..."] },
  "parameters": { "duration": 5, "resolution": "720P", "ratio": "9:16" }
}
```

旧版 `compshareMedia.ts` 把 `prompt` / `duration` / `resolution` 全部平铺在顶层,
还多加了一个服务端不认的 `task_type: "video_generation"`,所以一提交就被 reject。

**修复**:把最新版 `compshareMedia.ts`(`generateVideo` 已改写为嵌套 schema)重新粘到
Toonflow「设置 → 媒体模型」,**重启 Toonflow**(因为供应商文件改完要重启才生效)。

**进阶**:如果改完还 400,把 `errorText` 里的 `error.message` 贴回我,通常会告诉是
哪个具体字段不被接受。

### 10.4 视频任务提交成功但「未返回 task_id」

**症状**:节点 UI 报 `ModelVerse 视频任务未返回 task_id`(有时伴随
`ModelVerse 任务失败 / 轮询失败`)。说明请求体已通过校验(没有 400),
但响应字段读不到。

**根因**(2026-09-29 已修复):ModelVerse 任务提交 + 状态查询的真实响应都
嵌套在 `output` 字段里:
```json
{ "output": { "task_id": "..." }, "request_id": "..." }
```
而状态查询有时又包了一层 `data.output`。旧代码只查顶层 `task_id`,
所以每次都读不到。

**修复**:`compshareMedia.ts` 的 `generateVideo` 与 `pollTask` 都按
`output.task_id → data.task_id → 顶层 task_id → data.output.task_id`
四级 fallback 归一化;改完粘到 Toonflow 设置重启即可。

### 10.5 视频生成 HTTP 403「api key quota exceeded」

**症状**:`HTTP 403 Access forbidden: api key quota exceeded,
key_id=uminferapikey-xxx, daily_limit_amount=30, monthly_limit_amount=50`。

**根因**:这个 Key 在 ModelVerse 的账号配额桶里,**所有视频模型共享同一个配额
计数器**(切模型无效,因为同一个 key_id)。触发场景:
- 调试阶段手动重跑太多次(本次调试过程中累计 30+ 次)
- 同一周期内多个项目共用一个 Key

**修复**(按优先级):
1. **新建 Key**(推荐,5 分钟):console.compshare.cn → API Keys → 创建新 Key →
   粘到 Toonflow「设置 → 媒体模型」,新 Key 配额独立计数。
2. **等刷新**:daily 配额每天 UTC 0:00 重置,monthly 配额次月 1 日重置。
3. **找商务提配额**:实际生产用 30/天配额不够,提工单申请提升。

**省钱建议**:所有 6 个镜头都尽量用 `wan2.6-r2v-flash`(¥0.15/s)而不是
`wan2.7-i2v`(¥0.6/s),一集 30 秒视频成本从 ¥18 降到 ¥4.5(详见 §4.2.1)。

### 10.6 轮询报 UNABLE_TO_VERIFY_LEAF_SIGNATURE

**症状**(docker logs):
```
error: unable to verify the first certificate
path: "https://api.modelverse.cn/v1/tasks/status?task_id=..."
code: "UNABLE_TO_VERIFY_LEAF_SIGNATURE"
```

**根因**:Bun 的 fetch 在 macOS + Docker Desktop + 公司 HTTPS 代理环境下,
校验 ModelVerse 服务器证书链失败(Bun 默认不一定信任代理注入的中间证书)。

**修复**:`compose.yaml` 加一行 `NODE_EXTRA_CA_CERTS`,让 Bun 信任系统 CA bundle:
```yaml
services:
  toonflow:
    environment:
      - NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt
```
然后 `docker compose down && docker compose up -d` 重建容器。

### 10.7 视频生成卡在 Running

**症状**:videoNode 长时间不返回，最后提示超时，Docker 日志在等待期间没有明显报错。

**已确认的适配错误**:ModelVerse 返回 `output.task_status`，旧代码只读取 `status`，因此 `Success` 和 `Failure` 都会继续轮询直到 30 分钟超时。另外，成功地址 `output.urls[0]` 和失败原因 `output.error_message` 也未被读取。不能仅凭前端等待就判断平台任务仍在 Running。

**修复**:使用供应商版本 1.0.1 或更新版本，解析上述三个字段；缺失或未知状态立即报错，失败信息包含任务 ID 和平台原因。

Docker 实际加载 `/app/data/providers/compshareMedia.ts`，每次生成重新读取。更新前先备份该文件，再同步修复后的源码；仅修改仓库文件或重建镜像不会更新数据卷中的供应商。无需删除视频节点或重建工作区。已经开始的请求仍持有旧代码，修复应用于新发起的请求。

仍有失败时，通过 `docker compose logs --tail 100 toonflow` 查看具体原因，或使用供应商调试界面查看任务提交及状态响应。根据实际错误检查参数、额度或网络，避免盲目重复提交。

### 10.4 角色脸在不同镜头里不一样

## 11 · MiniMax 媒体供应商(图像 / TTS)

除了优云智算 ModelVerse,你也可以用 **MiniMax Token Plan 订阅**(`sk-cp-...`)直接调官方图像 / TTS,作为 ModelVerse 配额的备用通道(避免 §10.5 的 quota exceeded)。

### 11.1 安装

把 `compshare-integration/minimaxMedia.ts`(v1.0.0+)全文复制到
Toonflow 「设置 → 媒体模型 → 添加自定义供应商」对话框,保存。

支持的 4 个模型:

| 模型 | 类型 | 单价 | 备注 |
|---|---|---|---|
| `image-01` | 文生图 | 按套餐 | 1K/2K,1:1/3:4/4:3/9:16/16:9 |
| `image-01-reframe` | 文生图 + i2i | 按套餐 | subject_reference 接受 1 张参考图 |
| `speech-2.8-hd` | TTS | $100/M 字符 | 高清 |
| `speech-2.8-turbo` | TTS | $60/M 字符 | 快速 |

### 11.2 用法(同 ModelVerse)

- 角色立绘 / 分镜图:用 `image-01` 或 `image-01-reframe`(后者接 i2i)
- 配音:用 `speech-2.8-hd` 或 `speech-2.8-turbo`
- 在画布上拖一个图片生成节点 / 让 AI 助手调 `generateAudio` 工具

### 11.3 排错

#### 11.3.1 图片生成 HTTP 404 `404 page not found`

**症状**:节点报 `HTTP 404`,`errorText` 内容是 `404 page not found`。

**根因**(2026-09-29 已修复):MiniMax 真实端点**不是** `/v1/images/generations` 这种
OpenAI 风格的命名,而是单数 + 动名词 `/v1/image_generation`。旧版 `minimaxMedia.ts`
用了 `/images/generate`,直接被服务端按路径找不到路由 reject。

**修复**:新版 `minimaxMedia.ts` 已改为 `/v1/image_generation`,重新粘贴到 Toonflow 设置
重启即可。

**进阶排查**:如果还 404,把 curl 跑的完整命令 + 响应贴回来。常见会试错的路径:
`/v1/images/generations`、`/v1/images/generate`、`/v1/image/create`、`/v1/image/generate` —— 都返回 404,只有 `/v1/image_generation` 是 HTTP 200。

#### 11.3.2 图片字段名差异

**症状**:HTTP 200 但 `base_resp.status_code: 1002 / 1004`,提示 `param invalid` 或 `login fail`。

**根因**:MiniMax 用私有字段名,不是 OpenAI 风格:

| Toonflow / OpenAI 风格 | MiniMax 真实字段 |
|---|---|
| `ratio: "9:16"` | `aspect_ratio: "9:16"` |
| `quality: "high"` | `prompt_optimizer: true` |
| `image: [url]` (i2i) | `subject_reference: [{type:"character", image_file: url}]` |

**修复**:已在新版 `minimaxMedia.ts` 中处理,直接用最新版即可。如果用 Toonflow AI 助手直接调 API 而不是走供应商,记得手动换字段名。

#### 11.3.2a 「图像生成成功但未返回 URL」但 URL 在响应里

**症状**:HTTP 200 + 响应里能看到 `data.image_urls: ["https://..."]`,节点仍然报错
`MiniMax 图像生成成功但未返回 URL`。

**根因**(2026-09-29 已修复):URL 校验正则写错 —— 写成 `/^https?:\/\/\//`(3 个斜杠,匹配 `https:///`),
但真实的 URL 是 `https://...`(2 个斜杠),永远过不去校验。看上去 URL 在响应里能读出来,
实际解析时却把字符串当非 URL 跳过,最后抛出兜底错误。

**预防**:
1. 写完 vendor **必须真跑一张图**而不是只看 curl 200(curl 只验通链路,不验解析)
2. 正则用 `/^https?:\/\//`(2 斜杠)而不是 `/^https?:\/\/\//`(3 斜杠)
3. 已在新版 `minimaxMedia.ts` v1.0.1 修正,重新粘贴到 Toonflow 设置重启即可

#### 11.3.3 TTS HTTP 404

**症状**:`MiniMax TTS 失败：HTTP 404`。

**根因**:TTS 端点是 `/v1/text_to_speech`,**不是** `/v1/audio/speech`。

**修复**:新版 `minimaxMedia.ts` 已修正,重新粘贴即可。

#### 11.3.4 TTS body 字段差异

| OpenAI 风格 | MiniMax 真实字段 |
|---|---|
| `input: "..."` | `text: "..."` |
| `response_format: "mp3"` | `audio_setting.format: "mp3"` |
| `speed: 1` | `audio_setting.speed: 1` |

#### 11.3.5 TTS 返回非音频内容

**症状**:`MiniMax TTS 返回非音频内容：application/json ...`。

**根因**:MiniMax TTS 是**同步返回二进制音频流**(`Content-Type: audio/mpeg`),
不要用 OpenAI 的 `JSON { audio: { data: base64 } }` 协议来解。

**修复**:新版 `minimaxMedia.ts` 已用 `response.arrayBuffer()` 直接拿二进制,
按 `audio/mpeg` 或 `audio/wav` 解析。如果用其他供应商把 TTS 转发到 MiniMax,
记得不要走 JSON 路径。

### 11.4 国内 / 海外 base 切换

如果你的 MiniMax 账号是海外区,把供应商的 `baseUrl` 字段改成:
`https://api.minimax.io/v1`(去掉 `.com` 后缀)。
